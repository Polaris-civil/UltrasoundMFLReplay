# 20251221 超声—漏磁数据同步回放方案

## 1. 方案结论

本方案面向 2025 年 12 月 21 日同线路、同方向采集的超声和漏磁数据，目标是在一个窗口中完成同步浏览和连续回放：

- 上层显示超声 B-scan 回波数据；
- 下层显示漏磁左右两侧共16行信息；
- 漏磁每行继续叠加 X、Z 两个方向，因此下层实际显示32条波形；
- 两种模态共享同一个横轴；
- 横轴不使用虚假的超声 Mileage，而使用以接头为零点的相对距离；
- 四段漏磁和七段超声在程序中作为一个连续数据集回放；
- 原始数据保持不变，首先采用逻辑合并和按窗口读取。

这里的“合并为一个”指程序和用户看到的是一个整体数据集，不要求立即把所有原始 DAT 或 CSV 物理重写成单个大文件。

## 2. 建设目标与边界

### 2.1 建设目标

1. 建立可解释的接头对齐坐标。
2. 将 EX01～EX04 漏磁数据按线路顺序组织为一个连续数据流。
3. 将 S0～S6 超声数据按 ID 顺序组织为一个连续回波数据流。
4. 通过一个统一的窗口起点和窗口宽度驱动两个模态同步刷新。
5. 支持局部窗口回放、拖动、缩放、播放、暂停、跳转和接头定位。
6. 在数据缺失、段间边界和采集异常处保持真实空间关系，不人为压缩或伪造连续信号。

### 2.2 暂不纳入的内容

- 不在回放方案中重新训练漏磁模型。
- 不把超声数据直接加入当前漏磁异常分数。
- 不把超声回波点插值成连续波形。
- 不把两个模态强行重采样成相同记录条数。
- 不覆盖或破坏原始 EX、CSV 和现有二进制文件。
- 不把虚拟 Mileage 当作两个模态的最终物理坐标。

## 3. 数据现状

### 3.1 漏磁原始数据

来源目录：

~~~text
E:\trae\ultrasoundMFLReply_app\分发软件版本\data\20251221
~~~

目录下有四个连续采集段：

~~~text
EX01
EX02
EX03
EX04
~~~

每个段包含相同的32个通道：

~~~text
Left/Right × X/Z × Channel 1～8
~~~

每条 DAT 记录占6字节：

~~~text
int32 index，小端序
int16 value，小端序
~~~

四段数据统计如下。跨度按照该段首尾 index 和 0.57462 mm/index 估算，暂不包含额外段间空档。

| 段 | 每通道记录数 | 通道数 | index 末值 | 段内估算跨度 |
|---|---:|---:|---:|---:|
| EX01 | 72,600,000 | 32 | 107,300,245 | 61.657 km |
| EX02 | 49,200,000 | 32 | 70,046,329 | 40.250 km |
| EX03 | 72,600,000 | 32 | 113,012,938 | 64.939 km |
| EX04 | 33,800,000 | 32 | 47,398,711 | 27.236 km |
| 合计 | 228,200,000/通道 | 32 | — | 约194.083 km |

四段每通道合计约2.282亿条记录，32个通道合计约73.024亿个幅值数据。全部四段原始通道文件约43.8 GB，因此不适合在浏览器或 Python 绘图进程中一次性加载。

重要特征：

- 每个 EX 段的 index 都从0重新开始；
- 同一个 EX 段内各通道记录数一致；
- index 允许重复或停留，不能把它当作唯一记录编号；
- 当前 dataset/v1 的训练和异常结果主要对应 EX01，并不代表四段完整线路；
- EX01尾部存在明显的连续零值/采集终止特征，回放时应显示为数据状态，而不是普通缺陷波形。

### 3.2 超声原始数据

原始目录：

~~~text
E:\trae\ultrasound_data_analysis\data\raw\csv\20251221
~~~

当前正确的整体来源是7个无后缀合并文件：

~~~text
S0、S1、S2、S3、S4、S5、S6
~~~

每个合并 CSV 的原始字段为：

| 字段 | 作用 |
|---|---|
| Track | 股别，当前文档中 Track 0 为下股、Track 1 为上股 |
| ID | 超声位置编号，跨 S0～S6 连续 |
| GateNo | 闸门编号 |
| Depth | 深度采样编号 |
| TransmitSerialNo | 发射序号 |
| Amplitude | 回波幅值 |
| PulseWidth | 脉宽 |
| GateGain | 闸门增益 |
| Speed | 采集速度 |
| RailType | 钢轨类型 |
| Mileage | 当前数据中的虚拟里程，不作为统一物理横轴 |

7个合并文件共9,672,910条记录：

| 段 | 回波记录数 |
|---|---:|
| S0 | 431,826 |
| S1 | 440,415 |
| S2 | 661,588 |
| S3 | 1,767,503 |
| S4 | 1,754,976 |
| S5 | 2,465,240 |
| S6 | 2,151,362 |
| 合计 | 9,672,910 |

超声每条记录代表一个回波点，不是固定采样率下的连续波形。同一个 ID 可能有多个 GateNo、Depth 和 Track 组合，因此不能按超声记录行号与漏磁记录行号一一对应。

项目当前已经生成了超声回放二进制数据，记录布局为：

~~~text
mileage float32
id      uint32
depth   uint8
gate    uint8
track   uint8
segment uint8
~~~

单条记录12字节，共约116 MB。这个二进制数据适合按分片和位置范围读取。

注意：S0_0、S0_1 等后缀文件是合并文件按股别拆开的表示，不能和无后缀合并文件同时计数或同时加载，否则会重复。

### 3.3 数量与空间范围的区别

两种模态的原始记录量明显不同：

- 漏磁：每通道约2.282亿条连续记录，32通道共约73.024亿个幅值；
- 超声：约967万条稀疏回波记录。

但是，两边的横向位置范围接近：

- 漏磁四段按本地 index 顺序累加，约194.083 km；
- 超声 ID 范围为2,586,903～342,766,950，按相同尺度约195.474 km；
- 两者跨度差约1.392 km，约占超声 ID 跨度的0.712%。

这支持两种模态属于同一长距离检测范围，也支持使用相同的空间尺度进行接头对齐，但不意味着两边记录条数必须相同。

## 4. 统一坐标设计

### 4.1 坐标原则

统一横轴定义为：

~~~text
x_joint_m = 距离接头中心的有符号距离，单位为米
~~~

约定：

~~~text
x < 0：接头之前
x = 0：接头中心
x > 0：接头之后
~~~

统一空间尺度：

~~~text
scale_mm_per_unit = 0.57462
scale_m_per_unit  = 0.00057462
~~~

接头负责确定两个模态之间的固定位置偏移；相同尺度负责将接头之前和之后的数据放到同一个距离轴上。

### 4.2 漏磁坐标

漏磁需要先把每个 EX 段内的局部 index 转换成连续的 global_index：

~~~text
global_index(EXk, i) =
    segment_offset[EXk]
    + index(EXk, i)
    - index_first(EXk)
~~~

再以接头位置为原点：

~~~text
x_mfl =
    (global_index - joint_global_index)
    × 0.00057462
~~~

其中 segment_offset 不能只由 EX 文件名推断，应在位置映射表中明确记录。推荐使用以下字段：

| 字段 | 说明 |
|---|---|
| segment | EX01～EX04 |
| local_index_first | 本段第一个 index |
| local_index_last | 本段最后一个 index |
| global_start_unit | 全局起始位置单位 |
| global_end_unit | 全局结束位置单位 |
| gap_before_m | 本段前的物理空档 |
| valid_start/end | 有效数据范围 |
| status | valid、gap、dropout 或 uncertain |

如果确认段间没有物理空档，可以按 EX01→EX04 累加；如果存在漏采或文件切换空档，应在 segment_offset 中保留空档，不能把不同位置直接压在一起。

### 4.3 超声坐标

超声不使用 Mileage 作为横轴，直接使用跨 S0～S6 连续的 ID：

~~~text
x_us =
    (ID - joint_us_id)
    × 0.00057462
~~~

ID 可以重复，因为多个回波可能属于同一位置；绘图时重复横坐标是正常的散点现象。

超声现有数据虽然按虚拟 Mileage 分成约1 km 的二进制块，但 Mileage 只保留为存储分片、来源提示或鼠标悬停信息。统一回放查询应依据 ID 范围，而不是依据 Mileage 范围。

### 4.4 接头工作锚点

当前跨模态脚本中已经存在一组接头工作锚点：

~~~text
MFL joint record position：约584,064
US  joint ID：约2,794,006
中心偏移：约2,209,942.5 个位置单位
~~~

该锚点已经用于局部接头图的相对距离显示，但应作为工作标定值保存，不能把现有脚本中的硬编码视为最终不可变配置。

现有验证中，接头两端的响应带宽不完全一致，端点换算差异约0.2063 m。这更可能反映两种传感器对接头响应范围的定义不同，而不是简单的坐标错误。因此后续应区分：

- 接头中心对齐误差；
- 接头响应带宽差；
- 长距离累计漂移；
- 段间空档造成的位置偏移。

### 4.5 方向和股别配置

坐标映射中应显式保存方向符号：

~~~text
direction_sign = +1 或 -1
~~~

如果两个模态的采集方向一致，使用相同符号；如果一个方向相反，则对该模态坐标取反。

超声 Track0/Track1 与漏磁 Left/Right 的物理对应关系不能只根据名称硬编码。建议将其写入配置：

~~~json
{
  "track_to_rail": {
    "0": "unknown",
    "1": "unknown"
  },
  "mapping_status": "pending_manual_confirmation"
}
~~~

页面可以同时显示两种模态的全部股别，但在未确认映射前，不应在标题中声称某个 Track 一定对应某个 Left 或 Right。

## 5. 逻辑整体数据集设计

### 5.1 推荐原则

初期不物理合并原始文件，而是生成一个统一的回放清单。对回放程序而言，这个清单就是一个整体数据集。

建议的派生目录结构：

~~~text
outputs/synchronized_replay/20251221/
├─ manifest.json
├─ alignment.json
├─ mfl_segments.json
└─ ultrasound_index.json
~~~

这些清单可以引用原始数据目录，不要求复制原始 DAT 和 CSV。

### 5.2 manifest 建议内容

~~~json
{
  "dataset": "20251221",
  "coordinate": {
    "type": "joint_relative_distance",
    "unit": "m",
    "scale_mm_per_unit": 0.57462,
    "origin": "confirmed_joint_center",
    "direction_sign": 1
  },
  "joint": {
    "mfl_segment": "EX01",
    "mfl_local_index": 584064,
    "us_id": 2794006,
    "status": "working_anchor"
  },
  "mfl": {
    "segments": ["EX01", "EX02", "EX03", "EX04"],
    "display_rows": 16,
    "traces_per_row": 2,
    "record_dtype": "int32 index + int16 value"
  },
  "ultrasound": {
    "segments": ["S0", "S1", "S2", "S3", "S4", "S5", "S6"],
    "position_field": "ID",
    "ignored_axis_field": "Mileage",
    "record_size_bytes": 12
  }
}
~~~

### 5.3 物理合并作为后续可选项

如果将来确实需要一个物理大文件，可以基于已经确认的映射生成派生文件：

- 漏磁：每个通道按 EX01→EX04 重写为连续 global_index；
- 超声：只拼接7个无后缀合并 CSV，或将现有二进制块整理为一个逻辑文件；
- 原始 index、原始 Mileage、原始分段信息仍须在 manifest 中保留；
- 物理合并结果必须是 derived 数据，不能覆盖原始数据。

对回放而言，物理合并不是必要条件，且会增加约43.8 GB漏磁数据重写和校验成本。因此第一版应优先使用逻辑合并。

## 6. 整体回放流程

### 6.1 单一回放状态

前端只维护一套位置状态：

~~~text
window_start_m
window_width_m
play_position_m
play_speed_m_per_s
~~~

播放位置使用 x_joint_m，而不是某一边的记录序号。

### 6.2 每次窗口刷新

1. 根据 window_start_m 和 window_width_m 得到当前横轴范围。
2. 根据 MFL segment 映射表确定当前范围涉及哪些 EX 段。
3. 将全局 x 范围反查为各 EX 段内的局部 index 范围。
4. 通过内存映射读取漏磁16个显示行对应的 X/Z通道。
5. 将超声 x 范围换算为 ID 范围。
6. 根据 ID 范围跨二进制分片查询超声回波。
7. 将两类数据都转换为接头相对米制坐标。
8. 交给上、下两个渲染区域使用相同的横向像素变换。

### 6.3 不做等量重采样

漏磁保持连续波形语义，超声保持离散回波点语义：

- 漏磁：按屏幕像素做保峰值的 min/max 包络降采样；
- 超声：保留点的位置、Track、GateNo 和 Depth；
- 不使用行号插值来制造模态之间的对应关系；
- 同一个 x 位置允许出现多个超声回波点和多个漏磁幅值采样点。

### 6.4 段边界处理

当窗口跨过 EX 段边界时：

- 后端分别读取前后两个段；
- 前端按 global x 拼接；
- 在段边界绘制细竖线或背景标记；
- 如果存在空档，显示空白带；
- 不把前一段末值与后一段首值直接连成一条伪连续曲线。

当窗口跨过超声缺失区时：

- 不绘制回波点；
- 保留横轴距离；
- 在概览或状态栏中提示该区间无超声回波记录。

## 7. 推荐渲染架构

### 7.1 推荐方案

推荐使用：

~~~text
HTML/JavaScript 页面
        +
Canvas 2D 绘图
        +
本地 Python 数据服务
        +
内存映射 DAT 和现有超声二进制分片
~~~

原因：

1. 超声当前已经使用浏览器 Canvas，已有分片读取和筛选逻辑；
2. 漏磁总数据量很大，必须按窗口读取；
3. Canvas适合绘制超声散点和32条漏磁波形；
4. 两个面板可以共享同一套像素坐标变换；
5. 鼠标拖动、缩放、十字光标和播放控制更容易统一。

如果最终必须表现为传统桌面窗口，可以在外层使用 PySide6/QWebEngineView 加载同一个本地页面。页面和数据服务仍保持上述结构。

### 7.2 页面结构

~~~text
┌─────────────────────────────────────────────────────────────┐
│ 顶部控制栏：数据批次、接头定位、窗口宽度、播放、速度、筛选 │
├─────────────────────────────────────────────────────────────┤
│ 超声上层                                                     │
│   Track 0：回波散点，纵轴为名义深度                         │
│   Track 1：回波散点，纵轴为名义深度                         │
├─────────────────────────────────────────────────────────────┤
│ 漏磁下层                                                     │
│   Left  Ch1 X/Z                                              │
│   Left  Ch2 X/Z                                              │
│   ...                                                        │
│   Left  Ch8 X/Z                                              │
│   Right Ch1 X/Z                                              │
│   ...                                                        │
│   Right Ch8 X/Z                                              │
├─────────────────────────────────────────────────────────────┤
│ 统一横轴：接头相对距离（m），x=0 为接头中心                  │
│ 统一进度条：当前窗口、段边界、数据缺失和接头位置             │
└─────────────────────────────────────────────────────────────┘
~~~

超声内部的 Track0/Track1 是上下两个超声子面板；整个超声模块位于页面上方。漏磁模块位于页面下方，并默认显示左右两侧共16行。

### 7.3 漏磁行显示规范

行顺序固定为：

~~~text
第01～08行：Left  Channel 1～8
第09～16行：Right Channel 1～8
~~~

每行：

- 蓝色表示 X 方向；
- 橙色表示 Z 方向；
- 纵轴默认沿用当前漏磁显示范围约 -1.2～1.2；
- 行标题明确显示 Left/Right、Channel 和 X/Z；
- 行与行之间共享横轴，不共享纵轴；
- 可以提供“全16行”和“只看左/右侧”的显示开关，但全16行应作为默认目标布局。

### 7.4 超声显示规范

- 横轴使用接头相对距离；
- 纵轴使用 Depth 转换后的名义深度；
- 深度方向向下增加；
- Track0、Track1分别显示；
- GateNo通过颜色、符号或筛选器区分；
- 继续支持按 Track、GateNo 筛选；
- 不把超声回波连接成线；
- 对超过名义深度范围的 Depth 值使用异常标记。

### 7.5 共享光标和交互

任意面板发生以下操作时，另一面板同步更新：

- 鼠标移动；
- 鼠标点击；
- 横向拖动；
- 横向缩放；
- 键盘左右移动；
- 播放和暂停；
- 跳转到接头；
- 跳转到某个全局距离。

建议用一条跨上下区域的竖直光标显示当前位置，并在光标旁同时显示：

~~~text
x_joint_m
对应 MFL EX 段和局部 index
对应 US ID
对应原始 Mileage（仅作为附加信息）
~~~

## 8. 数据服务接口建议

### 8.1 元数据接口

~~~text
GET /api/replay/manifest?dataset=20251221
~~~

返回：

- 统一坐标定义；
- 接头锚点；
- EX段映射；
- S段和超声二进制分片索引；
- 数据有效范围；
- Track与Left/Right映射状态；
- 可用的窗口宽度和默认显示参数。

### 8.2 统一窗口接口

~~~text
GET /api/replay/window
    ?dataset=20251221
    &x_start=-5
    &x_end=5
    &mfl=both
    &channels=1,2,3,4,5,6,7,8
    &tracks=0,1
    &gates=all
~~~

返回内容分为：

~~~text
coordinate
  x_start、x_end、joint_position

mfl
  rows[16]
  每行的 x、x_value、z_value
  source_segment、local_index 范围

ultrasound
  x、depth、track、gate、id

coverage
  MFL段边界、无数据区、超声缺失区、采集异常区
~~~

### 8.3 传输格式

元数据可以使用 JSON；大量数据不建议全部使用 JSON 文本：

- 漏磁波形使用 Float32Array 或 Int16Array 二进制传输；
- 超声回波使用现有12字节记录或紧凑的结构化二进制；
- 响应中携带缩放和字段说明；
- 前端使用 ArrayBuffer/DataView 解析；
- 同一个请求携带 request_id，避免快速拖动时旧请求覆盖新位置。

## 9. 性能设计

### 9.1 漏磁

- 使用 numpy.memmap 打开DAT；
- 只读取当前窗口对应的记录；
- 不加载四段全部通道；
- 后端对每个屏幕像素桶保留最小值和最大值；
- 缩放到局部细节时再返回更高密度原始点；
- 使用最近窗口缓存；
- EX段边界切换时提前预取下一段。

漏磁信号中可能存在窄峰和饱和响应，因此不能只做普通平均降采样。min/max 包络能够保留异常峰值。

### 9.2 超声

- 继续使用当前二进制分片；
- 用 ID 范围定位分片和记录；
- 不扫描原始 CSV 作为实时回放数据源；
- 按 Track、GateNo 在服务端或前端过滤；
- 对超密集窗口可以按像素桶合并相同 Gate 的点，但必须保留原始点数和筛选状态；
- 虚拟 Mileage 只用于文件分片，不参与对齐。

### 9.3 概览与细节两级分辨率

全线回放不应直接绘制全部原始点，建议分为：

1. 概览层：按较大位置网格显示漏磁峰值、超声回波密度和段边界。
2. 细节层：进入8～10 m等局部窗口后，读取漏磁波形和超声散点。

这可以同时满足“整体浏览”和“局部回放”。

## 10. 数据质量和异常处理

### 10.1 必须显式标记的情况

- EX01～EX04 的 index 重置；
- EX段之间的物理空档或位置不确定；
- EX01尾部连续零值；
- US没有回波的区间；
- US ID重复；
- US GateNo缺失或本批次没有出现的闸门；
- Depth超过名义127范围；
- Speed为零的超声记录；
- Track与Left/Right尚未确认的映射状态。

### 10.2 不应做的处理

- 不把没有数据的区间压缩掉；
- 不把缺失区间插值成正常波形；
- 不把MFL段末和段首直接拼成一条连续曲线；
- 不把超声的虚拟Mileage重新当作绝对线路里程；
- 不把超声回波行号与MFL记录序号直接对应；
- 不把模型当前只有EX01的异常事件标记扩展到EX02～EX04。

### 10.3 当前起始里程字段的处理

四个漏磁 workparaminfo.dat 中的第二字段分别读到：

~~~text
EX01：4.9935
EX02：1162.1153
EX03：1217.1377
EX04：1282.8318
~~~

当前项目文档曾将 EX01 的4.9935解释为起始里程，但它与超声虚拟里程范围并不处于同一明显尺度。因此，统一回放第一版不依赖该字段，而采用接头相对距离。该字段可以保留为原始元数据，待业务含义确认后再作为第二坐标轴或提示信息。

## 11. 对齐验证方案

### 11.1 接头中心验证

至少记录以下内容：

- 漏磁接头起止 record/index；
- 漏磁接头中心；
- 超声接头起止 ID；
- 超声接头中心；
- 中心偏移；
- 两端响应宽度；
- Track构成；
- GateNo构成；
- 位置误差和置信度。

页面应把接头中心显示为 x=0，并允许在接头附近反复放大检查。

### 11.2 接头前后验证

在接头前后各选择若干可识别位置，比较：

- 漏磁突变或结构响应；
- 超声多闸门回波带；
- 位置差；
- 随距离增加是否出现累计偏移。

如果中心附近对齐但远端逐渐偏离，需要把问题记录为尺度漂移，而不是继续调整单一偏移量。

### 11.3 段边界验证

分别检查：

- EX01→EX02；
- EX02→EX03；
- EX03→EX04；
- S0→S1 等超声分片边界。

验证内容包括：

- 是否能正确切换源文件；
- 是否出现重复或跳跃位置；
- 横轴是否保持单调；
- 波形是否被错误连接；
- 超声 ID 是否继续递增；
- 空档是否被正确保留。

### 11.4 页面验收条件

第一版至少满足：

1. 超声模块位于上方。
2. 漏磁模块位于下方。
3. 漏磁默认显示Left/Right共16行。
4. 每行同时显示X/Z。
5. 上下模块横轴像素位置完全一致。
6. 接头中心在两个模块中都落在x=0。
7. 播放器可以从接头前连续播放到接头后。
8. 播放跨过EX段时不崩溃、不重复、不改变空间尺度。
9. 超声Mileage不参与统一横轴。
10. 缺失区间和采集异常区间有明确视觉提示。
11. 快速拖动时不会出现旧请求覆盖新位置。
12. 页面显示的源段和本地位置可以追溯到原始文件。

## 12. 分阶段实施建议

### 阶段一：坐标和数据清单

- 确认接头的MFL段、局部index和US ID；
- 建立EX01～EX04段间映射；
- 确认段间是否存在物理空档；
- 确认Track0/1与Left/Right的业务对应；
- 生成统一manifest；
- 不改动任何原始数据。

### 阶段二：统一读取层

- 为漏磁增加多段数据读取器；
- 支持全局x到EX段和局部index的反查；
- 为超声增加以ID为主的窗口查询；
- 统一返回接头相对距离；
- 增加覆盖范围和数据状态信息。

### 阶段三：统一页面

- 以现有超声Canvas页面为基础；
- 增加漏磁16行Canvas绘图区域；
- 将播放、拖动、缩放和光标改为共享状态；
- 保持超声Gate筛选；
- 增加MFL左右侧、通道和X/Z显示控制。

### 阶段四：性能和视觉优化

- 增加MFL min/max包络降采样；
- 增加全线概览；
- 增加窗口缓存和预取；
- 增加段边界、接头和缺失区标记；
- 检查不同窗口宽度下的交互流畅度。

### 阶段五：对齐验收

- 使用接头局部图验证中心；
- 使用接头前后位置验证固定偏移；
- 使用远端位置验证累计漂移；
- 由业务人员确认Track与Left/Right映射；
- 确认后再决定是否生成物理派生合并文件。

## 13. 关键风险与决策

| 风险或问题 | 处理决定 |
|---|---|
| MFL每个EX段的index重置 | 使用global_index和segment_offset |
| 超声Mileage为虚假里程 | 不作为统一横轴，使用ID |
| 两模态记录条数差异很大 | 保持原生数据密度，不做等量匹配 |
| MFL总量约43.8 GB | 内存映射、按窗口读取、保峰值降采样 |
| 超声回波是稀疏点 | 按散点绘制，不连接成连续线 |
| 四段MFL与七段US段数不一致 | 按各自位置映射，不按段号一一对应 |
| Track与Left/Right关系未最终确认 | 作为配置项，不在代码中隐式假设 |
| EX01 workparam起点字段有尺度疑点 | 第一版不依赖，使用接头相对坐标 |
| 当前漏磁模型结果主要覆盖EX01 | 回放原始四段与模型事件标记分开管理 |

## 14. 最终建议

第一版不建议直接把四段漏磁文件物理拼接成一个超大 DAT，也不建议把超声全部重新导出成一个巨大的 CSV。最稳妥的实施方式是：

~~~text
原始数据保持不变
        ↓
接头确定统一零点
        ↓
建立MFL四段和US七段的全局位置映射
        ↓
形成一个逻辑统一回放数据集
        ↓
Canvas页面上方显示超声
Canvas页面下方显示漏磁左右16行
        ↓
使用同一套接头相对距离横轴和播放状态
~~~

这样既符合接头对齐的业务标准，也保留两种传感器各自的数据语义和采样密度，并且可以在后续坐标验证完成后，再选择是否生成物理合并文件。

本方案文档只描述设计和验收要求，不代表已经执行数据合并或代码修改。
